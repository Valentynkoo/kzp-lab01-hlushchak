# kzp-lab01-hlushchak

Курс «Кросплатформні засоби програмування». Варіант 8 — **«Каталог фільмів»**.
Репозиторій наскрізний: лабораторна № 1 — перший прототип, лабораторна № 2 —
перебудова на власні класи (`Movie`, `YearRating`) без зміни зовнішньої поведінки,
лабораторна № 3 — спадкування й поліморфізм (`Movie` → `FeatureFilm`, `Documentary`).
Звіт про поточну роботу — `REPORT.md`, про лабораторну № 2 — `docs/REPORT-lab02.md`.

## Призначення

Консольна програма читає записи про фільми з CSV-файла, перевіряє їх,
обчислює чотири показники та виводить звіт у консоль і текстовий файл.
Хибні рядки не зупиняють програму: вони пропускаються з повідомленням про
номер рядка та причину.

## Формат входу

Файл `data/input.csv` у кодуванні UTF-8, один запис у рядку, поля розділені
крапкою з комою, десяткові числа — з крапкою:

```text
title;director;year;minutes;rating[;kind]
```

Шосте поле `kind` необов'язкове: `feature` (художній) або `documentary`
(документальний), регістр і пробіли не враховуються. Без нього фільм вважається
художнім, тому файли попередніх робіт читаються без змін. Невідомий або порожній
вид — помилка рядка.

## Правила валідації (інваріанти базового класу `Movie`)

| Поле | Тип | Правило |
|---|---|---|
| title | String | не null і не порожня |
| director | String | не null і не порожній |
| year | int | більше нуля |
| minutes | int | більше нуля |
| rating | double | скінченне число від 0 до 10 |

Перевірку виконує конструктор базового класу, тому некоректний об'єкт створити
неможливо в жодному підтипі. Перетворення рядка CSV на об'єкт виконує статичний
фабричний метод `Movie.fromCsv(String)`: він перевіряє структуру й типи, а
конструктор — значення; підтип створює сам `MovieKind`.

## Показники

1. Кількість коректних записів
2. Середній рейтинг
3. Найдовший фільм (назва і тривалість)
4. Найстаріший рік (рік і назва фільму)

Додатково (блок «Рекомендації» після основного звіту): найкращий фільм за
рекомендаційним балом, кількість фільмів за видом і кількість унікальних фільмів.

## Структура класів

```text
src/main/java/ua/lpnu/kzp/
├── Main.java                  # лише запускає процес і повертає код завершення
├── ArgumentParser.java        # розбір аргументів -> CliOptions
├── CliOptions.java            # record: help, version, input, output
├── ApplicationController.java # керує роботою, повертає код завершення
├── MovieCatalogProcessor.java # список Movie -> показники -> текст звіту
├── ProcessingResult.java      # record: підсумок обробки
├── Movie.java                 # абстрактний базовий клас: спільні поля, інваріанти, equals/hashCode
├── FeatureFilm.java           # підтип: художній фільм, штраф за тривалість понад 150 хв
├── Documentary.java           # підтип: документальний фільм, бонус за тривалість до 90 хв
├── MovieKind.java             # enum: FEATURE, DOCUMENTARY (код, підпис, створення підтипу)
├── YearRating.java            # record: пара «рік — рейтинг»
└── FileReport.java            # читання/запис файлів (UTF-8, Path)
```

Потік даних: CSV-рядок → `Movie.fromCsv` → `MovieKind.create` → `FeatureFilm` або
`Documentary` → `List<Movie>` → `ProcessingResult` → звіт.

## Спадкування й поліморфізм

Спільний метод `recommendationScore()` оголошено в `Movie` і по-різному реалізовано
в підтипах:

| Підтип | Формула бала |
|---|---|
| `FeatureFilm` | рейтинг × 10 − 0.1 за кожну хвилину понад 150 |
| `Documentary` | рейтинг × 10 + 0.1 за кожну хвилину, але не більше ніж за 90 хвилин |

Код звітності працює з типом `Movie` і не перевіряє підтип. Два фільми рівні, якщо
збігаються клас, назва, режисер і рік; `equals` і `hashCode` узгоджені, тому
`HashSet` не дублює рівні фільми. Обґрунтування вибору спадкування й опис рівності —
у `REPORT.md`.

## Вимоги

JDK 21. Maven Wrapper (`mvnw` / `mvnw.cmd`) входить до репозиторію, окремо
встановлювати Maven не потрібно.

## Збірка та запуск

```text
mvnw.cmd verify
mvnw.cmd package
java -jar target/lab01-<версія з pom.xml>.jar
```

На macOS та Ubuntu замість `mvnw.cmd` використовуйте `./mvnw`.
Версію продукту задано лише в `pom.xml`; у програму її підставляє Maven під час збірки.

Параметри:

```text
java -jar target/lab01-<версія>.jar --help
java -jar target/lab01-<версія>.jar --version
java -jar target/lab01-<версія>.jar --input data/input.csv --output out/report.txt
```

Коди завершення: `0` — успіх, `1` — хибні аргументи, `2` — помилка читання
вхідного файла або запису звіту.

Якщо в консолі Windows замість українських літер з'являються «кракозябри»,
виконайте перед запуском `chcp 65001`. Файл звіту завжди записується в UTF-8.

## Приклад

Вхід — `data/input.csv` (5 коректних і 3 хибні рядки). Вивід основного звіту:

```text
Показник                       Значення
Коректних записів                     5
Середній рейтинг                   7.32
Найдовший фільм: Плем'я (132 хв)
Найстаріший фільм: Земля (1930 рік)

Помилок: 3
Рядок 3: очікується 5 полів, отримано 4
Рядок 5: числове поле має помилковий формат
Рядок 7: від'ємне числове значення
```

Після нього дописується блок рекомендацій:

```text

Рекомендації
Найкращий за рекомендаційним балом: Тіні забутих предків (81.00)
Фільмів за видом: художній: 5, документальний: 0
Унікальних фільмів: 5
```

Той самий текст записується у `out/report.txt`. Основний звіт збігається з виводом
лабораторної роботи № 1 (це перевіряє `BehaviorComparisonTest`). Приклад з обома
підтипами — `data/input-mixed.csv`:

```text
java -jar target/lab01-<версія>.jar --input data/input-mixed.csv --output out/mixed.txt
```
